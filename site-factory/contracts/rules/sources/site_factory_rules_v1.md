# Site Factory 상위노출 설계 규칙 v1

버전: v1.0  
목적: 지역 서비스 웹사이트를 자동 생성·확장할 때, 현재까지의 네이버 웹문서 실증 연구 결과를 실제 사이트 제작 규칙으로 전환한다.

> 이 문서는 “네이버 알고리즘 정답”이 아니라, 현재 표본에서 반복 관찰된 패턴과 운영상 합리적인 구조 원칙을 분리해 정리한 실전 설계 규칙이다.

---

## 1. 설계 원칙의 우선순위

### MUST — 반드시 적용
현재 연구에서 가장 일관되게 지지된 요소이거나, 검색어-문서 대응을 위해 필수적인 구조.

1. 검색지역 + 정확한 서비스 조합별 전용 랜딩페이지를 만든다.
2. 한 페이지는 하나의 핵심 서비스 의도에 집중한다.
3. Title, H1, 본문 첫 구간에서 페이지의 지역·서비스를 명확히 일치시킨다.
4. 검색어와 실제 페이지가 다루는 서비스가 어긋나지 않도록 한다.
5. URL은 고유해야 하며, 같은 검색의도를 여러 URL이 중복 타깃하지 않도록 한다.
6. 페이지는 index 가능한 상태여야 하며, canonical·robots·status code 등 기본 기술 요건을 만족해야 한다.
7. 생성 페이지는 사이트 구조 안에서 최소 한 곳 이상 연결되어야 한다. 완전 고아 페이지를 만들지 않는다.

### SHOULD — 권장
현재 표본에서 순위효과가 확정되지는 않았지만, 구조·크롤·확장성·사용자 탐색 측면에서 강하게 권장되는 원칙.

1. 지역 허브 → 서비스 허브 → 상세 랜딩 구조를 사용한다.
2. 본문 안에서 실제 관련 지역/서비스 문서를 문맥형 링크로 연결한다.
3. breadcrumb 또는 상하위 계층을 표현하는 탐색 구조를 제공한다.
4. 인접 지역·관련 서비스 문서를 묶어 사이트의 주제망을 만든다.
5. 사이트맵과 내부링크 구조를 함께 유지한다.
6. 자동생성 문서라도 페이지 목적과 CTA는 명확하게 유지한다.
7. 지역/서비스별 문서군을 일관된 템플릿으로 운영하되, 검색의도에 필요한 섹션은 달리한다.

### OPTIONAL — 선택
순위 필수요소로 보기는 어렵지만 사용자 경험과 전환에는 도움이 될 수 있는 요소.

- FAQ
- Schema markup
- 이미지 다수
- 긴 본문
- 후기/사례
- 가격표
- 체크리스트
- 표/리스트
- 동영상
- 작성일/수정일
- OG metadata

### NOT SUPPORTED — 순위 공식으로 사용하지 말 것
현재 연구에서는 순위를 보장하는 규칙으로 지지되지 않았다.

- 무조건 3,000자 이상
- 내부링크를 특정 개수 이상 넣기
- footer에 전국 지역 링크를 수백 개 삽입
- 키워드를 특정 횟수 반복
- URL에 반드시 키워드 삽입
- FAQ가 있으면 상위노출
- Schema가 있으면 상위노출
- 이미지가 많으면 상위노출
- 사이트맵 URL 수가 많으면 상위노출
- 자동생성 페이지는 불리하다
- 커스텀 도메인이 pages.dev보다 무조건 유리하다

## 2. 키워드 → 페이지 매핑 규칙

Site Factory의 핵심은 “키워드 생성”보다 “검색의도별 전용 페이지 배정”이다.

### 기본 식

지역 × 서비스 × 의도

예:

- 수원 × 근조화환 × 주문
- 수원 × 축하화환 × 개업
- 수원 × 꽃배달 × 당일배송
- 수원역 × 꽃배달 × 배송시간
- 인계동 × 꽃집 × 추천
- 아주대병원 × 근조화환 × 장례식장배송

### 페이지 분리 기준

다음 중 하나라도 서비스 목적이 다르면 별도 페이지를 우선한다.

- 상품/서비스가 다름
- 검색 사용자의 행동 목적이 다름
- 검색자가 기대하는 정보가 다름
- CTA가 다름
- 가격/배송/후기/주문 등 핵심 섹션이 달라야 함

### 한 페이지로 합칠 수 있는 경우

- 동의어 수준
- 검색의도가 사실상 동일
- 동일한 CTA로 해결 가능
- 같은 본문 구조로 자연스럽게 설명 가능

예:

“수원 근조화환 주문”
“수원 장례식화환 주문”

→ 같은 페이지에서 대응 가능

반면:

“수원 근조화환”
“수원 개업화환”

→ 별도 페이지 권장

## 3. 사이트 구조 기본형

권장 기본 구조:

```text
/
├─ region/
│  ├─ suwon/
│  │  ├─ funeral-wreath/
│  │  ├─ opening-wreath/
│  │  ├─ same-day-delivery/
│  │  └─ places/
│  │     ├─ suwon-station/
│  │     ├─ ingyedong/
│  │     └─ ajou-university-hospital/
│  └─ ansan/
│     └─ ...
│
├─ services/
│  ├─ funeral-wreath/
│  ├─ opening-wreath/
│  ├─ flower-basket/
│  └─ same-day-delivery/
│
├─ occasions/
│  ├─ funeral/
│  ├─ opening/
│  ├─ promotion/
│  └─ anniversary/
│
└─ guide/
   ├─ ordering/
   ├─ delivery-time/
   ├─ pricing/
   └─ etiquette/
```

핵심은 URL 모양 자체가 아니라, 실제 정보구조가 아래처럼 동작하는 것이다.

```text
지역 허브
   ↓
지역 + 서비스
   ↓
장소/상황/의도 상세
```

## 4. 페이지 유형 정의

Site Factory는 모든 페이지를 같은 템플릿으로 만들지 않는다.

### A. REGION_SERVICE_LANDING
예: 수원 근조화환

필수 요소:
- 지역 + 서비스 명확한 H1
- 서비스 범위
- 주문/문의 CTA
- 지역 대응 가능 설명
- 관련 장소/지역 링크

### B. PLACE_LANDING
예: 아주대병원 장례식장 근조화환

필수 요소:
- 장소명
- 위치/접근/배송 관련 정보
- 실제 주문 시 필요한 정보
- 해당 장소에서 발생할 수 있는 실무 조건
- 관련 지역/서비스 링크

### C. INTENT_LANDING
예: 수원 꽃배달 당일배송

필수 요소:
- 검색자의 목적에 바로 답변
- 가능 여부
- 조건
- 시간
- 주문 절차
- CTA

### D. PRICE_GUIDE
예: 수원 근조화환 가격

필수 요소:
- 가격 결정 요소
- 옵션/상품군
- 추가 비용 조건
- 가격 예시 또는 범위
- 주문 CTA

### E. INFORMATION_GUIDE
예: 근조화환 문구 / 조문 예절

필수 요소:
- 정보 자체가 중심
- 서비스 판매 페이지와 구분
- 필요 시 관련 상품/지역 랜딩으로 연결

### F. HUB
예: 수원 꽃배달

역할:
- 직접 모든 키워드를 먹는 장문 페이지가 아니라
- 수원 관련 서비스·장소·상황 페이지를 정리하고 연결하는 중심 노드

## 5. Title 규칙

Title은 페이지가 어떤 검색을 해결하는지 즉시 보여줘야 한다.

### 기본 구조

`[지역/장소] + [정확한 서비스] + [핵심 의도]`

예:

- 수원 근조화환 주문 | 당일 장례식장 배송
- 수원 개업화환 배달 | 축하화환 주문
- 아주대병원 장례식장 근조화환 | 당일 배송 안내
- 수원 꽃배달 당일배송 | 주문 시간과 배송 안내

### 금지

- 모든 페이지에 같은 제목 패턴 복제
- 지나치게 많은 키워드 나열
- 해당 페이지가 실제 다루지 않는 서비스 삽입
- 지역명만 바꾸고 내용이 전혀 다른 의도인 제목

---

## 6. H1 규칙

H1은 하나를 기본값으로 한다.

Title과 완전히 동일할 필요는 없지만 핵심 지역·서비스는 일치해야 한다.

예:

Title:
`수원 근조화환 주문 | 장례식장 당일배송`

H1:
`수원 근조화환 주문과 장례식장 당일배송 안내`

---

## 7. 본문 구조 규칙

본문은 글자 수를 맞추는 방식으로 만들지 않는다.

### 기본 랜딩 구조

1. 즉답 영역
2. 서비스 설명
3. 지역/장소 특성
4. 이용 조건
5. 주문/진행 방법
6. 비용/시간/주의사항
7. 관련 서비스 또는 지역
8. CTA

### 첫 화면에서 답해야 할 것

사용자가 다음을 빠르게 알 수 있어야 한다.

- 여기서 해당 서비스를 받을 수 있는가
- 해당 지역/장소 대응이 가능한가
- 어떻게 주문/문의하는가
- 시간/가격/조건은 무엇인가

---

## 8. 지역 고유정보 규칙

지역정보는 “분량 채우기”가 아니라 서비스 수행에 필요한 범위에서 넣는다.

좋은 지역정보:
- 주요 배송 장소
- 장례식장/병원/상권
- 접근성
- 배송 소요
- 주차/진입
- 지역별 추가배송 조건
- 해당 지역에서 실제 주문 시 필요한 정보

불필요한 지역정보:
- 지역 역사
- 관광지
- 인구
- 유명 맛집
- 서비스와 무관한 일반 설명

---

## 9. 내부링크 규칙

내부링크 수를 목표로 잡지 않는다.

### 링크 우선순위

1. 상위 허브
2. 같은 지역의 관련 서비스
3. 같은 서비스의 인접 지역
4. 실제 관련 장소
5. 사용자 다음 행동에 필요한 정보

### 예

수원 근조화환 페이지:

```text
수원 꽃배달 허브
수원 장례식장 목록
아주대병원 장례식장 근조화환
성빈센트병원 장례식장 근조화환
용인 근조화환
화성 근조화환
근조화환 주문방법
근조화환 문구 안내
```

### 피해야 할 구조

- footer에 전국 모든 도시 수백 개 나열
- 관련 없는 서비스 링크 삽입
- 모든 페이지에서 동일한 100개 링크
- 키워드 앵커를 억지로 반복

## 10. 허브 설계 규칙

허브는 SEO용 링크 창고가 아니다.

### 지역 허브

예: `/suwon/`

포함:
- 대표 서비스
- 상황별 서비스
- 주요 장소
- 주문 가이드
- 인접 지역
- 최신/주요 문서

### 서비스 허브

예: `/services/funeral-wreath/`

포함:
- 서비스 설명
- 주요 지역
- 장소별 안내
- 가격
- 주문방법
- FAQ/가이드

### 역할

허브는:
- 페이지 발견
- 계층 명확화
- 사용자 탐색
- 크롤 경로
- 문서군 관리

를 위한 구조적 중심이다.

순위효과 자체는 현재 연구에서 확정하지 않는다.

---

## 11. URL 규칙

URL에 키워드가 반드시 들어갈 필요는 없다.

중요한 것은:
- 고유성
- 안정성
- 일관성
- 너무 깊지 않은 구조
- 의미 있는 계층

권장:

```text
/suwon/funeral-wreath/
/suwon/places/ajou-hospital/
/services/funeral-wreath/suwon/
```

숫자 ID도 가능하지만 관리성을 고려하면 사람이 이해 가능한 URL을 우선한다.

---

## 12. Programmatic SEO 규칙

자동생성 자체는 금지하지 않는다.

허용:
- 동일 구조
- 동일 디자인
- 동일 CTA
- 동일 데이터 필드
- 지역/서비스에 따른 자동 조합

반드시 달라져야 하는 것:
- Title
- H1
- 서비스 목적
- 핵심 지역
- 실제 제공 정보
- 관련 내부링크
- 장소/상황 데이터
- 검색의도별 핵심 섹션

금지:
- 지역명만 치환한 의미 없는 복제
- 존재하지 않는 서비스/장소/가격 생성
- 서로 다른 URL이 동일한 검색의도를 중복 타깃

---

## 13. 초기 공개 규칙

초기 공개 페이지 수 자체를 순위요인으로 보지 않는다.

권장:
- 핵심 허브
- 대표 서비스
- 핵심 지역
- 주요 장소
- 상업 의도 높은 검색어

를 우선 공개.

예:

```text
1차
홈
지역 허브
서비스 허브
핵심 지역+서비스
주요 장소

2차
동/면 단위
세부 상황
가격/시간/후기/가이드

3차
롱테일 조합
```

페이지 수보다 구조 완성도를 우선한다.

---

## 14. Indexing 규칙

생성 완료 ≠ 작업 완료.

각 페이지 상태를 관리한다.

필드 권장:

```text
draft
published
indexable
submitted
crawled
indexed
impression_detected
ranking_detected
needs_revision
```

자동 점검:
- HTTP 200
- noindex
- canonical
- sitemap 포함
- 내부 inbound link
- 404
- orphan candidate
- title 중복
- H1 중복
- content duplicate candidate

---

## 15. 중복/카니발리제이션 규칙

한 검색어에 여러 페이지가 경쟁하지 않도록 한다.

예:

나쁜 구조:

```text
/suwon-flower/
/suwon-flower-delivery/
/suwon-flower-order/
/suwon-fast-flower/
```

모두 사실상 “수원 꽃배달”을 노림.

좋은 구조:

```text
/suwon/flower-delivery/
/suwon/funeral-wreath/
/suwon/opening-wreath/
/suwon/same-day-delivery/
```

검색의도별 역할이 분명해야 한다.

## 16. 품질 게이트

페이지 공개 전 자동 검사.

### 필수 통과

- HTTP 200
- index 가능
- canonical 정상
- Title 존재
- H1 존재
- 지역 확인
- 서비스 확인
- CTA 존재
- 최소 1개 inbound internal link
- 중복 slug 없음
- 동일 의도 페이지 충돌 없음

### 경고

- 본문 지나치게 짧음
- 지역정보 없음
- 관련 링크 없음
- 이미지 alt 없음
- 메타 description 없음
- FAQ 없음
- Schema 없음

경고는 발행 차단 조건이 아니다.

## 19. 실전 순위 학습 루프

이제부터 Site Factory 자체 데이터로 규칙을 개선한다.

페이지별 기록:

```text
URL
타깃 키워드
발행일
색인일
첫 노출일
첫 클릭일
최고 순위
현재 순위
impressions
CTR
```

비교:

- 동일 template
- 동일 업종
- 다른 지역
- 다른 service
- 다른 intent

성공 페이지와 실패 페이지를 비교한다.

이 데이터가 쌓이면 v1.1부터는 외부 경쟁사이트 연구보다 자사 실증 데이터를 우선한다.

## 20. Site Factory v1 최종 규칙

### MUST

- 지역 × 서비스 전용 랜딩
- 검색 서비스와 실제 페이지 서비스 일치
- Title/H1에 핵심 지역·서비스 명확화
- 한 페이지 한 핵심 검색의도
- index 가능한 기술 상태
- 중복 타깃 방지
- 최소 1개 사이트 내부 연결

### SHOULD

- 지역 허브
- 서비스 허브
- breadcrumb
- 관련 지역 문맥링크
- 관련 서비스 문맥링크
- 장소/상황별 상세문서
- sitemap + 내부링크 동시 관리
- programmatic 문서군의 일관된 구조

### OPTIONAL

- FAQ
- Schema
- 긴 본문
- 다수 이미지
- 후기
- 동영상
- 표
- 작성일

### NOT SUPPORTED

- 3,000자 규칙
- 키워드 특정 반복 횟수
- 내부링크 특정 개수
- footer 링크 대량 삽입
- 무조건 keyword URL
- sitemap 대형화 자체
- 자동생성 자체를 페널티 요소로 가정
- 커스텀 도메인 자체를 랭킹 우위로 가정

---

## 21. v1 적용 후 판단 기준

v1은 완성된 알고리즘이 아니라 첫 실전 규칙이다.

다음 데이터가 쌓이면 업데이트한다.

- 30개 이상 index 확인
- 20개 이상 impression 발생
- 10개 이상 유의미한 ranking 관측
- 서로 다른 page type에서 성과 확인

그때:

```text
v1
→ 실제 발행
→ ranking data
→ 성공/실패 비교
→ v1.1
```

로 수정한다.

---

## 22. 핵심 문장

Site Factory의 목표는 “페이지를 많이 만드는 것”이 아니다.

목표는:

> 검색자가 입력한 지역과 정확한 서비스를 정확한 한 페이지에 연결하고,
> 그 페이지를 사이트 전체 구조 안에서 발견·이해·탐색할 수 있게 만드는 것

이다.
